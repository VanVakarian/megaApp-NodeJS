### 🧠 Умный Каталог Продуктов: Архитектурный Концепт

#### Цель
Провести рефакторинг модуля "Каталог продуктов", создав гибкую и персонализированную систему. Новая архитектура должна обеспечить удобное управление продуктами для небольшой группы доверенных пользователей (семьи), заложить фундамент для интеграции с AI-сервисами (LLM/Vision) и улучшить общий пользовательский опыт.

#### Концепция и Архитектура
В основе новой системы лежит гибридная **двухуровневая модель каталога**, разделяющая личное и общее пространство для данных.

1.  **Личный Каталог (`Personal Scope`)**
    *   Основное рабочее пространство и "песочница" для каждого пользователя.
    *   **Ключевой момент:** Все новые продукты, созданные пользователем (вручную или с помощью LLM), **по умолчанию попадают в его Личный Каталог**.
    *   **Видимость:** Записи в этом каталоге видны **только их владельцу**. Это решает проблему приватности и "творческого беспорядка".
    *   Идеально подходит для личных рецептов, специфических продуктов и экспериментальных записей, сгенерированных AI.

2.  **Базовый (Семейный) Каталог (`Family Scope`)**
    *   Общая, выверенная база продуктов, которая служит "единым источником правды" для всей семьи.
    *   **Принцип наполнения:** Продукты попадают сюда только после того, как владелец явным образом **"поделится"** ими из своего Личного Каталога.
    *   **Видимость:** Продукты в Базовом Каталоге видны **всем пользователям** приложения.

3.  **Взаимодействие и User Flow**
    *   **Создание:** `Пользователь` → `Добавить продукт` → Запись создается в **Личном Каталоге**.
    *   **Публикация:** `Пользователь` → `Нажать "Поделиться"` → `scope` продукта меняется с `personal` на `family`.
    *   **Поиск:** При добавлении еды в дневник поиск идет **одновременно по Личному и Базовому каталогам**, с приоритетом отображения личных результатов.
    *   **"Избранное":** Пользователь может "забрать себе" любой продукт из Базового Каталога. Это не копирует запись, а создает быструю ссылку (`UserFavoriteProduct`) для удобного доступа.

#### Модель Данных и Ключевые API

##### Сущности БД (Высокоуровнево)
*   **`FoodProducts`** (замена `foodCatalogue`)
    *   **Атрибуты:** `id`, `name`, нутриенты (`kcals`, `proteins`, `fats`, `carbs`), `ownerId` (FK на `users`), `scope` (`'personal'` | `'family'`), `metadata` (JSON для AI-данных).
*   **`UserFavoriteProducts`** (замена `selectedCatalogueIds`)
    *   **Атрибуты:** `userId`, `productId`. Таблица-связка для "избранного".

##### Ключевые API эндпоинты
*   `POST /api/food/products` — Создает новый продукт с `scope: 'personal'`.
*   `PUT /api/food/products/:id/share` — Меняет `scope` на `'family'`, делая продукт видимым для всех.
*   `GET /api/food/products` — Возвращает комбинированный список из Личного и Базового каталогов для текущего пользователя.
*   `POST /api/food/favorites` — Добавляет продукт в избранное пользователя.

#### Подготовка к AI-интеграции
Предложенная архитектура нативно поддерживает будущие AI-функции:

*   **LLM (Текст → КБЖУ):** Результат генерации нейросетью — это новый `FoodProduct` в **Личном Каталоге** пользователя. Он не "засоряет" общую базу, пока владелец не проверит и не решит им поделиться. Это исключает конфликты и дублирование.
*   **Vision (Фото → Еда + Вес):** Система распознает название еды и ищет его в **объединенном каталоге** (Личный + Базовый), предлагая пользователю наиболее релевантные варианты для добавления в дневник.
